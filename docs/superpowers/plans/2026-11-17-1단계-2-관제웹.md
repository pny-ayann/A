# 1단계-2 관제 웹 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 회사 직원이 PC 브라우저에서 오더를 접수하고, 실시간으로 지켜보고, 강제 배차·회수·상태 변경·문의 처리를 하고, 업체·기사·요금표·직원 계정을 관리하는 관제 웹을 만든다. 실제 Supabase 무료 서버에 연결해 동작을 확인한다.

**Architecture:** `apps/admin`에 Next.js(App Router) 앱을 둔다. 데이터는 브라우저와 서버 모두 supabase-js로 읽고 쓰며, 규칙은 ① 서버 기반의 RLS와 RPC가 지킨다. 서비스 키가 필요한 일(계정 만들기, 카카오 REST 호출)만 Next.js 서버 액션/라우트에서 한다. 화면이 아닌 판단 로직(폼→저장 데이터, 실시간 변경 반영, 경고 계산, 카카오 응답 해석)은 `apps/admin/src/lib`의 순수 함수로 빼서 Vitest로 TDD 한다. 화면은 각 작업 끝에 내장 브라우저로 실제 서버에 붙여 확인한다.

**Tech Stack:** Next.js 15(App Router, TypeScript strict), `@supabase/supabase-js` v2, `@supabase/ssr`, Tailwind CSS, 카카오맵 JS SDK, 다음 우편번호 서비스(키 없음), 카카오 로컬 REST API(주소→좌표·동네), 카카오모빌리티 길찾기 REST API(도로 거리), Vitest, Supabase CLI(`npx supabase`, Docker 불필요한 `link`/`db push`만 사용)

**Spec:** `docs/superpowers/specs/2026-11-16-1단계-오더흐름-design.md` (8장 관제용 화면이 이 계획의 범위). 서버 규칙과 이름은 `supabase/migrations/*`와 `docs/superpowers/plans/2026-11-16-1단계-1-서버기반.md`의 Interfaces를 그대로 쓴다.

## Global Constraints

- **저장소가 공개(PUBLIC)다.** 키, 비밀번호, 테스트 계정 비밀번호는 절대 커밋하지 않는다. 모두 `apps/admin/.env.local`(git 제외)에만 둔다. 커밋 전마다 `git diff --cached`에 키 모양 문자열이 없는지 확인한다.
- `SUPABASE_SERVICE_ROLE_KEY`, `KAKAO_REST_KEY`는 서버 전용. 이름에 `NEXT_PUBLIC_`을 붙이지 않고, `"use client"` 파일에서 import 하지 않는다. 서버 전용 모듈 맨 위에 `import 'server-only'`.
- 브라우저용: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_KAKAO_JS_KEY`.
- 사용자가 직접 해야 하는 일(가입, 키 발급, `.env.local`에 비밀번호 넣기, `npx supabase login`)은 Claude가 대신 하지 않는다. 쉬운 한국어로 단계별 안내만 한다.
- 화면 문구는 한국어. 서버 오류는 `@takson/shared`의 `errorMessage()`로 보여 준다.
- PC 화면 기준(가로 1280px 이상). 관제 웹은 직원(`role = 'staff'`)만 들어온다.
- 관리자 전용 화면(직원 계정, 요금표·미션, 운영 설정, 수수료율, 업체 등록·설정, 기사 승인·정지, 변경 기록)은 일반 관제에게 메뉴를 숨기고, 서버 액션도 `is_admin`을 다시 확인한다. 최종 방어는 DB RLS.
- 오더의 상태·배정 기사는 반드시 `staff_assign` / `staff_unassign` / `staff_set_status` RPC로 바꾼다(직접 update는 DB가 거부함).
- 커밋은 작업마다 (사용자 허락됨). 푸시와 PR은 사용자에게 물어본다.
- 개발 서버: `npm run dev -w apps/admin` → http://localhost:3000. 화면 확인은 `.claude/launch.json`의 `admin` 설정으로 내장 브라우저에서 한다.

## Review Focus

1. **세션 만료·로그아웃 상태에서 관제 페이지 접근**: 로그인 화면으로 보내야 하고 데이터가 잠깐이라도 보이면 안 된다 → Task 2의 `middleware` 판정 함수 테스트.
2. **고객·기사 계정으로 관제 웹 로그인**: 비밀번호가 맞아도 "직원 계정이 아니에요"로 막고 바로 로그아웃 → Task 2 테스트.
3. **실시간 이벤트 순서가 뒤섞이거나 같은 이벤트가 두 번 올 때**: 목록이 중복되거나 옛 값으로 덮이면 안 된다 → Task 6 `applyChange` 테스트(updated_at 비교).
4. **카카오 API 실패(키 오류, 한도 초과, 주소 없음)**: 접수 화면이 멈추지 않고 "거리를 못 구했어요, 요금을 직접 입력하세요"로 진행 가능 → Task 5 `parseDirections`/`parseAddress` 실패 테스트.
5. **같은 아이디로 계정 두 번 만들기, 허용 안 되는 아이디**: 한국어 오류로 알려 주고 반쯤 만들어진 계정이 남지 않아야 한다 → Task 4 `createAccount` 테스트.
