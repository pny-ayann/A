# 2단계-1 기사 정산 (충전금 장부·출금 신청·주유비 지급·오더 번호) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기사별 충전금 장부를 서버가 자동으로 쓰고(후불 80% 적립·현금 수수료 차감·주유비 지급), 마이너스면 배차를 막고, 기사는 앱에서 잔액·내역·출금 신청을, 관리자는 관제 웹에서 충전·조정·출금 처리·주유비 지급을 한다. 모든 앱에 사람이 읽는 오더 번호를 보인다.

**Architecture:** 돈은 `wallet_entries` 한 표에 한 줄씩 쌓고 잔액은 합으로만 구한다(잔액 칸 없음). 오더 정산은 트리거가 "이 오더가 지금 상태라면 기사별로 얼마여야 하나 − 이미 적힌 합"의 차이만 적는다. 출금·충전·조정·주유비 지급은 security definer RPC로만 쓴다. 앱은 RPC `wallet_summary`와 장부 select만 쓴다.

**Tech Stack:** Supabase Postgres(마이그레이션, RLS, plpgsql, PGlite 테스트), Expo 기사 앱, Next.js 관제 웹, `@takson/shared`, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-2단계-1-기사정산-design.md` (앞 설계: `2026-11-16-1단계-오더흐름-design.md`)

## Global Constraints

- 수수료 기본 **20%** (`settings.default_commission_rate`), 기사별 `driver_rates.commission_rate`가 있으면 그것. 수수료 = round(요금 × 비율 / 100), 원 단위 정수.
- 후불 정산: 들어오는 시각 = 완료 + **10분**, 출금 가능 = 완료한 날(Asia/Seoul)의 **다음 날 12:00** (Asia/Seoul).
- 현금 오더: −수수료, 완료 즉시.
- 잔액 < 0 이면 `claim_order`·`staff_assign` 거절 `BALANCE_NEGATIVE` — 단 정산이 켜져 있을 때만(`settings.settlement_start_at is not null`).
- 자동 정산은 `completed_at >= settlement_start_at` 인 오더만.
- 장부 이름 문구(정확히): `후불 오더 완료 (1119-007)`, `현금 오더 수수료 (1119-008)`, `정산 변경 (1119-007)`, `주유비 지급 (1119-007)`, `주유비 변경 (1119-007)`, `시작 잔액`, `충전`, `조정: <사유>`, `출금 신청`, `출금 거절: <사유>`.
- 오더 번호 `MMDD-NNN` (Asia/Seoul 접수일 + 그날 순번 3자리, 1000부터 4자리).
- 충전·조정·시작 잔액·출금 지급/거절 = **관리자만**. 주유비 지급 = **관제 전체**. 받을 계좌·출금 신청 목록 = 본인 + 관리자만.
- 비밀값은 커밋하지 않는다. 서버 적용·배포는 사용자 허락 후.
- 사용자 문구는 쉬운 한국어. 오류 코드는 `packages/shared/src/errors.ts`에 한국어로.

## Review Focus

1. **동시에 출금 신청 두 번**(두 번 누르기, 두 기기): 합이 출금 가능 금액을 넘으면 안 됨 → Task 4 테스트 `동시에 두 번 신청해도 출금 가능 금액을 넘지 않는다` (기사 행 잠금).
2. **완료 → 되돌림 → 다시 완료, 요금 변경, 기사 변경, 후불↔현금 변경이 섞임**: 기사별 합이 항상 최종 상태의 목표 금액과 같음 → Task 2 테스트 `여러 번 바뀌어도 기사별 합은 최종 목표와 같다`.
3. **정산 켜기 전에 완료된 오더를 나중에 고침**: 장부 줄이 생기지 않음 → Task 2 테스트 `정산 시작 전에 완료된 오더는 고쳐도 장부가 없다`.
4. **완료 10분 안에 되돌림**: 잔액이 잠깐도 마이너스가 되지 않아 배차가 막히지 않음 → Task 2 테스트 `10분 안에 되돌려도 잔액은 0 아래로 내려가지 않는다`.
5. **주유비 지급 뒤 영수증 금액이 고쳐지거나 지워짐**: 차이만 장부에 → Task 5 테스트 `지급한 영수증을 고치면 차이만 적힌다`.
