# 서류탁송 1단계 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 오더 종류에 서류탁송을 더하고, 서류 사진(등록증·인감·캐피탈 양식) 올리기 → 관제 인정/불인정 → 인정돼야 운행 시작, 작성 예시 보기, 촬영 맞춤 테두리를 만든다.

**Architecture:** 서버 규칙은 마이그레이션 1개(`20261127000026_docs_order.sql`)에 모으고 PGlite 테스트로 고정한다. 서류 사진은 기존 `order-photos` 버킷 `{order}/docs/{slot}.jpg` + 새 표 `order_documents`, 예시 양식은 새 비공개 버킷 `capital-examples`. 세 앱은 서버 함수 이름·오류 코드만 바라본다.

**Tech Stack:** Supabase(Postgres, Storage, RLS), PGlite + Vitest, Expo(React Native, expo-router, expo-camera), Next.js 관제웹.

**Spec:** `docs/superpowers/specs/2026-11-27-서류탁송-design.md` (1단계만. 2단계 휴대폰 AI는 이 계획에 없음)

## Global Constraints
- 저장소는 공개. `예시서류/`(gitignore됨), `.env*`, 비밀값은 절대 커밋하지 않는다. 예시 사진은 서버 비공개 버킷에만.
- 이미 적용한 마이그레이션(≤ `20261126000025`)은 고치지 않는다. 새 파일은 `20261127000026_docs_order.sql` 하나.
- 서버 적용(`npx.cmd supabase db push --remote --yes`)과 예시 사진 올리기 스크립트 실행은 **사용자 허락을 받고** 한다. 적용 뒤 `supabase/.applied-migration`을 `20261127000026`으로.
- 오더 종류 값: `'takson'`(일반탁송), `'docs'`(서류탁송), `'daeri'`(대리). 화면 글자: 일반탁송 / 서류탁송 / 대리. 표시 배지 글자 "서류", 색은 경고색(기사 앱 `color.warn`, 관제웹 `bg-orange-100 text-orange-800`).
- 서류 칸 slot 값: `'registration'`(자동차등록증), `'seal'`(인감), 캐피탈 = 예시의 `capital_examples.id`(uuid 문자열). 화면 이름: 자동차등록증 / 인감(본인서명사실확인서) / 예시의 `title`.
- 문서 상태: `'pending' | 'approved' | 'rejected'`. 화면: 관제 확인 중 / ✓ 인정 / ✗ 불인정.
- 불인정 이유 기본 목록(관제웹): 잘림, 흐림, 빠진 칸, 도장·서명 없음, 용도 틀림(일반용·자동차공매용 아님), 수량 다름, 기타(직접 입력).
- 새 오류 코드: `CAPITAL_REQUIRED`, `DOCS_REQUIRED`, `DOCS_NOT_APPROVED`, `SEAL_COUNT_REQUIRED`. `packages/shared`의 `errorMessage`에 쉬운 한국어로 추가.
- 반납(취소) 시간·정산·청구에서 `docs`는 일반탁송과 같다(`kind = 'daeri'`만 따로).
- 쉬운 한국어, 기사 앱 글자 크기·버튼 높이(44 이상)는 기존 kit 그대로.

## Review Focus
1. 관제가 인정한 뒤 기사님이 같은 칸을 다시 찍으면 → 그 칸은 다시 `pending`, 운행 시작이 다시 막혀야 한다.
2. 서류탁송인데 캐피탈 예시가 하나도 없는(또는 표지뿐인) 회사 → 캐피탈 칸 0개, 등록증·인감만으로 진행 가능해야 한다.
3. 관리자가 예시를 지운 뒤 이미 올라온 그 칸 서류 → 남은 서류는 보이되 빠진 칸 계산에서 빠져야 한다(지운 예시는 더 요구하지 않음).
4. 다른 기사·다른 업체 고객이 서류 사진·예시 파일을 읽으려 할 때 → 서류는 거부, 예시는 로그인한 사용자 모두 읽기(개인정보 없는 양식이므로).
5. 일반탁송·대리 오더 → 서류 검사가 전혀 끼어들지 않아 지금과 똑같이 운행 시작되어야 한다.
각 줄의 테스트는 Task 1에 있다.
