# 1단계-3 기사 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 탁송 기사가 안드로이드 휴대폰 앱으로 로그인(또는 가입 신청)하고, 열린 오더를 잡고, 사진을 찍어야만 운행을 진행하고, 주유를 기록하고, 관제와 문의하고, 위치와 푸시 알림으로 관제·고객과 실시간으로 이어지게 한다.

**Architecture:** `apps/driver`에 Expo(React Native, expo-router) 앱을 둔다. 서버 규칙은 ① 서버 기반의 RLS·RPC(`claim_order`, `release_order`, `advance_order`, `report_location`, `missing_photos`, 사진·영수증 저장소 정책)를 그대로 쓰고, 이 계획에서 서버에 더하는 것은 푸시 발송(마이그레이션 0013) 하나다. 화면이 아닌 판단 로직(가입 입력 검사, 카드 정렬, 다음 버튼, 반납 남은 시간, 길안내 주소, 사진 대기열, 압축 크기, 운행 내역 합계, 위치 추적 여부)은 `apps/driver/src/lib`의 순수 함수로 빼서 Vitest로 TDD 한다. 화면은 Claude가 `expo start --web`을 내장 브라우저로 열어 먼저 확인하고, 카메라·위치·푸시처럼 휴대폰에서만 되는 것은 사용자의 안드로이드 폰(Expo Go, 마지막엔 시험용 설치 파일)으로 확인한다.

**Tech Stack:** Expo SDK 최신(`create-expo-app@latest`, Expo Go가 지원하는 버전), expo-router, TypeScript strict, `@supabase/supabase-js` v2 + `@react-native-async-storage/async-storage`(로그인 유지), expo-camera, expo-image-manipulator, expo-file-system, expo-location + expo-task-manager, expo-notifications, `@react-native-community/netinfo`, Supabase `pg_net`(푸시 발송), Expo 푸시 API, EAS Build(무료), Vitest

**Spec:** `docs/superpowers/specs/2026-11-16-1단계-오더흐름-design.md` — 4장(기사 가입), 5장(상태 흐름, 반납, 동시 보유), **6장 기사용 화면 전체**, 9.1(안드로이드 먼저, APK 직접 배포, EAS)이 이 계획의 범위. 서버 이름과 규칙은 `supabase/migrations/*`를 그대로 쓴다.

## Global Constraints

- **저장소가 공개(PUBLIC)다.** 키·비밀번호·`google-services.json`은 절대 커밋하지 않는다. 앱 설정은 `apps/driver/.env`(git 제외), 예시는 `apps/driver/.env.example`(이름만). 커밋 전마다 `git diff --cached`에 키 모양 문자열이 없는지 확인한다.
- 앱에 들어가는 값은 `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` 둘뿐. 서비스 키는 앱에 절대 넣지 않는다.
- 사용자가 직접 해야 하는 일(Expo 계정, Firebase 프로젝트, Supabase 대시보드 설정, 휴대폰에서 QR 찍기·설치)은 Claude가 대신 하지 않는다. 쉬운 한국어로 단계별 안내만 한다. 외부 계정 설정 변경은 매번 사용자 허락.
- 화면 문구는 한국어. 서버 오류는 `@takson/shared`의 `errorMessage()`로 보여 준다.
- 현장용: 주요 버튼 높이 56 이상, 글자 16 이상, 한 손 조작(중요 버튼은 화면 아래). (설계 10장 실패 조건)
- 사진은 **앱 안 카메라로만**. 갤러리 선택 기능을 만들지 않는다(`expo-image-picker` 쓰지 않음).
- 실시간 구독은 반드시 `subscribeAuthed`로(로그인 토큰을 붙인 뒤). anon 구독 금지.
- 상태 변경은 RPC로만(`claim_order`, `release_order`, `advance_order`). 버튼을 눌렀을 때 위치를 함께 보낸다(없으면 null).
- 오더 잠금 판단(사진 다 됐나)은 **서버 `missing_photos` 결과**로 한다. 휴대폰에만 있는 사진은 "업로드 대기"로 세고 버튼을 열지 않는다.
- 커밋은 작업마다. 푸시와 PR은 사용자에게 물어본다. `mycar-auto/`, `docs/agents/`는 건드리지 않는다.
- 사용자에게 주는 명령에는 `&&`를 쓰지 않고, `npx.cmd`를 쓴다.

## Review Focus

1. **지하 주차장처럼 신호가 없을 때 사진 5장을 찍고 앱을 껐다 켬**: 사진이 사라지지 않고, 신호가 오면 저절로 올라가고, 다 올라가기 전에는 "운행 시작"이 잠겨 있어야 한다 → Task 5 `queue` 테스트(저장·복원·재시도) + 기기 확인.
2. **같은 칸을 다시 찍음 / 업로드 중 같은 사진이 두 번 올라감**: 대기열에 한 장만 남고, 서버에도 칸당 한 줄만(같은 경로 upsert, 영수증은 미리 정한 id로 중복 무시) → Task 5·6 테스트.
3. **오더가 관제에 회수·취소된 뒤 대기열에 남은 사진**: 영원히 재시도하며 배터리를 쓰지 않고, 권한 거부면 버리고 "관제가 오더를 회수했어요" 안내 → Task 5 `applyResult('drop')` 테스트.
4. **두 기사가 동시에 잡기, 반납 시간이 막 지난 순간 반납**: 서버 오류를 한국어로 보여 주고 목록을 새로 고침 → Task 3·4 (서버가 이미 막음, 앱은 문구와 새로고침).
5. **로그인 세션이 끝난 채 백그라운드 위치 작업이 돎**: 오류로 계속 깨어나지 않고 위치 작업을 멈춤, 앱을 열면 로그인 화면 → Task 7 `shouldTrackInBackground` 테스트(세션 없음 → false).
