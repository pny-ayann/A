# 1단계-1 서버 기반 (데이터베이스와 규칙) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기사 앱, 고객 앱, 관제 웹이 함께 쓸 Supabase 데이터베이스 구조, 권한(RLS), 오더 규칙(잡기, 반납, 사진 필수 진행, 관제 조작)을 만들고 테스트로 증명한다.

**Architecture:** 규칙은 전부 데이터베이스 안(Postgres 함수, 트리거, RLS)에 둔다. 그래야 앱을 우회해도 규칙을 피할 수 없다. 앱은 테이블 직접 조회와 RPC 함수 호출만 한다. 테스트는 Docker 없이 PGlite(WASM Postgres)에 Supabase의 `auth`/`storage` 스키마 흉내(stub)를 깔고 실제 마이그레이션 SQL을 돌린다.

**Tech Stack:** npm workspaces, TypeScript(strict), Vitest, `@electric-sql/pglite`, Postgres SQL/plpgsql (Supabase 마이그레이션 형식)

**Spec:** `docs/superpowers/specs/2026-11-16-1단계-오더흐름-design.md`

**전체 1단계 계획 순서:** ① 이 문서 → ② 관제 웹 → ③ 기사 앱 → ④ 고객 앱. ②~④는 이 문서의 Interfaces를 그대로 쓴다.

## Global Constraints

- 저장소 루트: `탁송어플/` (git, 원격 `pny-ayann/A`, 기본 브랜치 `main`). 작업 브랜치 `feat/phase1-foundation`.
- `mycar-auto/` 폴더는 건드리지 않고 커밋에 넣지 않는다. `git add`는 항상 경로를 지정한다.
- **커밋은 사용자가 허락한 경우에만** 한다 (`CLAUDE.md` 규칙). 허락이 없으면 커밋 단계는 건너뛰고 보고에 적는다.
- `.env`, 비밀 키는 절대 커밋하지 않는다.
- Docker 없음. DB 테스트는 PGlite로만 한다.
- 오더 상태 값: `open`(접수), `assigned`(배차됨), `arrived_pickup`(출발지 도착), `driving`(운행 중), `completed`(완료), `cancelled`(취소).
- 오더 종류: `takson`(탁송), `daeri`(대리). 결제: `cash`(현금), `postpaid`(후불). 배차 방식: `open`(공개), `staff_only`(관제 배차 전용).
- 필수 사진 칸(slot) 5개: `front`, `back`, `left`, `right`, `dashboard`. 단계(phase): `pickup`(출발), `dropoff`(도착), `extra`(추가, 칸 없음).
- 운영 설정 기본값: 탁송 반납 10분, 대리 반납 5분, 예약 간격 30분, 미배차 경고 10분.
- 규칙 위반은 `raise exception` 메시지에 **영문 대문자 코드**만 넣는다 (예: `ALREADY_TAKEN`). 한국어 문구는 `packages/shared`의 `errorMessage(code)`가 만든다.
- 로그인 아이디는 Supabase Auth 이메일 `<아이디>@takson.local`로 바꿔 쓴다.
- 관제 등급: `admin`(관리자), `operator`(일반 관제). 직원 계정, 요금표, 미션, 운영 설정, 수수료율, 업체 등록·설정, 기사 승인·정지는 **admin만** 바꾼다. 그 밖의 오더 업무는 두 등급 모두 가능.

- [ ] **Step 2: `stubs.sql` 작성**

Supabase가 실제로 제공하는 것만 흉내 낸다. 마이그레이션은 이 stub이 없는 실제 Supabase에서도 그대로 돌아야 한다.
- 역할: `anon`, `authenticated`, `service_role` (nologin). `grant usage on schema public to authenticated, anon`, 그리고 `alter default privileges in schema public grant all on tables to authenticated` / `grant execute on functions to authenticated` (Supabase 기본 권한과 동일).
- `auth.users(id uuid primary key default gen_random_uuid(), email text unique, raw_app_meta_data jsonb default '{}', raw_user_meta_data jsonb default '{}', created_at timestamptz default now())`
- `auth.uid()` = `nullif(current_setting('request.jwt.claims', true)::json->>'sub', '')::uuid`
- `storage.buckets(id text primary key, name text, public boolean default false)`, `storage.objects(id uuid default gen_random_uuid(), bucket_id text, name text, owner uuid, created_at timestamptz default now())` + `alter table storage.objects enable row level security`, `storage.foldername(name text) returns text[]` = `string_to_array(name, '/')`의 마지막 요소를 뺀 배열. `authenticated`에 `storage` 사용과 objects 권한 부여.
