# 탁송 플랫폼 1단계 설계: 오더 흐름

작성일: 2026-11-16

## 1. 왜 만드는가

사용자는 탁송 회사를 운영하고 있다. 지금은 규모가 작지만 나중에는 기사와 업체 직원 수백 명이 쓸 수 있다.
주문 하나를 **고객(업체)**, **관제(회사 직원)**, **기사** 세 쪽이 같은 화면처럼 실시간으로 보고 처리하게 만드는 것이 목적이다.
지금 당장 실제 운영에 쓸 수 있는 것부터 만들고, 나중에 기능과 규모를 늘린다.

## 2. 전체 단계 (합의됨)

| 단계 | 내용 |
|---|---|
| **1단계 (이 문서)** | 오더 접수와 예약 → 오픈 배차와 강제 배차 → 사진이 있어야 진행되는 운행 → 완료. 기사 앱, 고객 앱, 관제 웹 실시간 연동 |
| 2단계 | 정산: 수수료, 주유비 정산, 현금과 후불 정산, 업체 청구서, 미수금, 업체별 단가 |

(처음에는 3단계로 기사 정식 앱을 따로 두었지만, 사용자가 기사와 고객을 처음부터 휴대폰 앱으로 하기로 해서 1단계에 합쳤다.)

1단계에서도 2단계에 필요한 데이터(요금, 결제 방식, 주유비 금액과 영수증)는 **기록해 둔다**. 다만 정산 계산과 지급 처리는 2단계에서 한다.

## 3. 만드는 방식 (Approaches)

| 방식 | 장점 | 단점 | 결정 |
|---|---|---|---|
| A. 웹앱 하나 + Supabase | 앱스토어 없이 며칠 안에 실제 사용 가능 | 화면을 끄면 기사 위치 전송이 멈춤, 아이폰 푸시 제한, 갤러리 사진을 막을 수 없음 | 처음에 선택했다가 바꿈 |
| **B. 기사·고객은 휴대폰 앱 + 관제는 웹** | 백그라운드 위치, 푸시 알림, 카메라 전용 촬영이 확실히 됨 | 스토어 등록이 필요하고 첫 사용까지 더 걸림 | **선택** |
| C. 노코드 툴 | 가장 빠름 | 업체별 규칙, 권한, 수수료 같은 복잡한 규칙을 감당 못 함 | 제외 |

사용자가 B를 선택했다: **기사와 고객은 휴대폰 앱, 관제는 웹.** 저장소 `CLAUDE.md`의 기존 기술 방향(React Native + Expo, Supabase, 카카오맵, Expo 푸시)과 같다. 관제가 웹이라는 점만 `CLAUDE.md`에 반영한다.
`CLAUDE.md`에 있던 앱 내 결제(토스페이먼츠)는 사용자 요구가 현금과 후불뿐이라 1단계에서는 제외한다. 필요해지면 2단계 이후에 다시 다룬다.

### 기술 구성 (Claude의 결정)
- **저장소 구조**: 한 저장소 안에 기사 앱, 고객 앱, 관제 웹을 두고 데이터 타입과 요금, 규칙 계산 코드를 공유한다.
- **기사 앱, 고객 앱**: React Native + Expo (TypeScript). 안드로이드와 아이폰 둘 다 빌드할 수 있는 구조로 만든다.
- **관제 웹**: Next.js (TypeScript), PC 화면 기준.
- **서버**: Supabase. 데이터베이스(Postgres), 실시간 연동(Realtime), 로그인(Auth), 사진 저장(Storage), 행 단위 권한(RLS)을 씀.
- **지도와 거리**: 카카오맵(지도, 주소 검색), 카카오모빌리티 길찾기 API(요금 계산용 도로 거리).
- **알림**: Expo 푸시 알림 (무료).
- **배포**: 관제 웹은 Vercel 무료. 앱 배포 방법은 9.1 참고.
- 계정 생성(Supabase, 카카오 개발자, Vercel, Expo, 스토어 개발자 계정)은 사용자가 직접 하고, Claude가 단계별로 안내한다.

## 4. 사용자와 계정

| 역할 | 누가 | 계정 |
|---|---|---|
| 고객 | 매매상사, 딜러 같은 **업체**와 그 직원 | 업체 하나에 직원 로그인 여러 개 |
| 기사 | 탁송 기사 | 1인 1계정 |
| 관제 | 회사 직원 | **관리자**와 **일반 관제** 두 등급 |

- 로그인은 **아이디와 비밀번호**로 한다. 업체 계정과 기사 계정은 관제가 만들어 준다. (Claude의 결정: B2B 위주라 자체 가입이 필요 없고, 문자 인증 비용도 들지 않는다.)
- 기사는 스스로 가입 신청을 할 수도 있다. 이때 면허증과 보험 서류 사진을 올리고, 관제가 승인해야 일을 받을 수 있다.

## 5. 오더 상태 흐름

```
접수 ──(오픈 배차: 기사가 잡음 / 강제 배차: 관제가 지정)──▶ 배차됨
배차됨 ──▶ 출발지 도착 ──[출발 사진 필수]──▶ 운행 중 ──[도착 사진 필수]──▶ 완료

어느 단계에서든: 관제는 취소, 배차 회수, 재배차, 상태 되돌리기 가능
고객은 배차 전까지만 직접 취소 가능 (배차 후에는 관제에 문의)
```

- **오더 종류**: **탁송**과 **대리** 두 가지. 사용자가 반납 시간을 종류별로 다르게 말해서 종류 구분을 넣는다. (Claude의 해석: 대리운전 오더도 같은 흐름으로 처리. 1단계에서 두 종류의 차이는 반납 가능 시간뿐이다.)
- **예약 오더**: 고객이 날짜와 시간을 지정한다. 기사 목록에 바로 노출되고, 카드에 **[예약] 11/18 14:00** 배지를 크게 표시한다. 예약 시간 순으로 정렬한다.
- **관제 배차 전용** (Claude의 결정): 관제가 오더를 만들거나 수정할 때 "관제 배차 전용"으로 표시하면 기사 목록에 나오지 않고 강제 배차로만 배정된다. 기본값은 공개.
- 모든 상태 변경은 **누가, 언제, 어디서(위치)** 했는지 이력으로 남는다.

### 5.1 기사 반납 (사용자 결정)
- 기사는 오더를 잡은 뒤 **탁송은 10분, 대리는 5분 안에만** 스스로 반납할 수 있다. 그 뒤에는 관제를 통해서만 회수된다.
- 반납 가능 시간(분)은 관제의 설정 화면에서 종류별로 바꿀 수 있다.
- 반납된 오더는 다시 목록에 올라가고, 기사별 반납 횟수는 관제가 볼 수 있다.

### 5.2 동시 보유 제한 (사용자 결정)
- 예약이 아닌 오더는 **한 번에 1건만** 잡을 수 있다.
- 예약 오더는 여러 건 잡을 수 있다. 단, 이미 잡은 다른 예약 오더와 **예약 시간이 앞뒤로 30분 이상 떨어져 있어야** 잡을 수 있다.
- 예약이 아닌 오더를 진행 중일 때는, 예약 시간이 지금부터 30분 안인 예약 오더는 잡을 수 없다. (Claude의 해석)
- 30분 간격은 관제 설정에서 바꿀 수 있다. (Claude의 결정)
- 조건에 걸리면 "잡기" 버튼을 눌렀을 때 이유를 보여준다.
- 관제의 강제 배차는 이 제한을 넘을 수 있고, 넘을 때 경고만 보여준다.

## 6. 기사용 화면

### 6.1 주문 목록 (오픈 배차)
각 카드에 표시하는 것:
- 출발지와 도착지 (구, 동 수준 요약)
- **내 현재 위치에서 출발지까지 거리** (직선 거리 km. 목록에서는 길찾기 API를 쓰지 않음)
- 요금, **현금 / 후불** 표시
- 예약이면 [예약] 배지와 시간
- "잡기" 버튼. 두 명이 동시에 누르면 먼저 누른 한 명만 성공하고, 나머지에게는 "이미 배차된 오더" 안내

### 6.2 진행 중인 오더
- 출발지와 도착지 전체 주소, 연락처. **주소를 누르면 카카오맵 또는 티맵 길안내**, **연락처를 누르면 전화**
- 차량 정보, 고객이 남긴 기사 메모, 경유지와 미션
- 상태 버튼: 출발지 도착 → 운행 시작 → 도착 완료

### 6.3 사진 규칙 (미등록 시 진행 불가)
- **출발 사진**: 앞, 뒤, 왼쪽, 오른쪽, **계기판**(주행거리와 연료량이 보이게) 5장이 필수. 다 올리기 전에는 "운행 시작" 버튼이 비활성.
- **도착 사진**: 같은 5장이 필수. 다 올리기 전에는 "도착 완료" 버튼이 비활성.
- 추가 사진(기존 흠집 등)은 장수 제한 없이 선택으로 올림.
- 사진은 앱 안 카메라로 찍는 게 기본이다. 촬영 시각과 위치를 함께 저장한다. (2026-11-28 사용자 결정) 미리 받아 둔 서류·차량 사진은 휴대폰 갤러리에서 여러 장을 골라 남은 칸에 한 번에 올릴 수 있다. 갤러리 사진은 위치를 붙이지 않고 `source = gallery`로 남겨, 관제웹 사진·서류 옆에 "갤러리" 표시가 붙는다.
- **신호가 없을 때** (지하 주차장 등, Claude의 결정): 찍은 사진은 휴대폰에 임시 보관되고, 신호가 잡히면 자동으로 올라간다. 버튼은 **서버에 업로드가 끝난 뒤에만** 열린다. 화면에 "업로드 대기 3장"처럼 표시한다.
- **사진 압축과 저장** (사용자 결정: 압축으로 무료 유지, 유료는 나중에 검토): 올리기 전에 휴대폰에서 긴 변 1600px, 장당 약 200~300KB로 줄인다. 오더당 약 3MB라 무료 1GB로 약 300~400건을 보관한다. 사용량이 80%를 넘으면 관리자 화면에 경고를 띄우고, 그때 유료 전환(월 $25)이나 무료 대안(Cloudflare R2 무료 10GB)을 다시 검토한다.
- **관제의 사진 예외** (사용자 결정): 기사 휴대폰 고장 같은 경우 **모든 관제**가 사유를 적고 사진 없이 다음 단계로 넘길 수 있다. 오더에 "사진 없이 진행 – 처리자, 사유"가 남는다. 기사와 고객에게는 이런 우회로가 없다.

### 6.4 주유비
- 운행 중 "주유 등록": 영수증 사진 + 금액. 여러 번 등록할 수 있음.
- 1단계에서는 기록만 하고, 관제가 볼 수 있다. 승인과 정산은 2단계.

### 6.5 기타
- 내 운행 내역(오늘, 이번 달 건수와 요금 합계). 수수료를 뺀 실수령액 계산은 2단계.
- 오더별 문의 채팅 (관제와)
- 새 오더, 강제 배차, 요금 변경, 관제 메시지는 **푸시 알림**으로 알린다. 앱이 꺼져 있어도 온다.
- 위치: **배차된 오더가 있는 동안**에는 화면이 꺼져 있어도 일정 간격으로 위치를 보낸다. 오더가 없을 때는 앱이 켜져 있을 때만 보낸다. (Claude의 결정: 배터리와 개인정보 때문에 일이 없을 때는 계속 추적하지 않는다.) 상태 버튼을 누를 때마다 위치를 찍는다.

## 7. 고객용 화면 (업체)

### 7.1 오더 접수
- 출발지와 도착지: 주소 검색(카카오), 상세 주소, 담당자 이름과 연락처
- **자주 쓰는 주소 10개**: 그 업체에서 많이 쓴 주소 상위 10개를 자동으로 띄우고, 직접 고정할 수도 있다. (Claude의 결정: 직접 등록만 하게 하면 관리를 안 해서 비게 된다.)
- 경유지 (선택, 여러 개)
- 차량 정보: 차량번호, 차종, 색상(선택), 변속기(오토/수동)
- 기사 메모
- 미션 (선택): 정해진 항목 중 고르고, 항목마다 추가 요금이 있다. 항목과 요금은 관제가 관리한다.
- 예약 여부와 날짜, 시간
- 결제 방식: 업체 기본값(현금 또는 후불)이 자동 선택되고 바꿀 수 있다.
- 요금: 거리 구간표로 자동 계산되어 보이고, **배차 전에는 고객이 자유롭게 고칠 수 있다.**

### 7.2 요금 수정 규칙 (사용자 결정)
- **배차 전**: 고객이 자유롭게 수정.
- **배차 후**: 기본은 수정 불가. 단, **도착지 변경, 경유지 추가, 미션 추가**를 할 때만 요금을 함께 바꿀 수 있다. 사유가 기록되고 기사와 관제에 즉시 알림이 간다.
- 관제는 언제든 수정 가능.
- 배차 후 요금이 바뀌면 기사는 알림만 받고 따로 동의하지 않는다. 이의가 있으면 문의 채팅으로 관제에 알린다. (Claude의 결정)

### 7.3 진행 확인
- 내 업체 오더 목록과 상태 (실시간)
- 배정된 기사 이름과 연락처, 운행 중인 기사의 실시간 위치
- 배차, 출발, 도착 완료 같은 상태 변화는 푸시 알림으로 받는다.
- 출발 사진과 도착 사진 보기
- 오더별 문의 채팅 (관제와)

### 7.4 주유비
- 주유비 부담이 "고객 청구"인 업체는 오더별 주유비와 영수증을 볼 수 있다. 정산 화면은 2단계.

## 8. 관제용 화면

관제는 **모든 권한**을 가진다. 일반 관제와 관리자의 차이는 8.5에 있다.

### 8.1 오더 관제판
- 전체 오더를 상태별로 보는 목록 + 지도 (출발지, 도착지, 기사 마지막 위치)
- 미배차 오더가 일정 시간(기본 10분) 지나면 빨간색으로 강조
- 필터: 업체, 기사, 상태, 날짜, 예약 여부

### 8.2 오더 처리
- **고객별 오더 접수**: 업체를 고르면 그 업체의 자주 쓰는 주소, 기본 결제 방식이 그대로 적용된 접수 화면
- **모든 항목 수정**: 주소, 요금, 결제 방식, 차량 정보, 메모, 상태
- **강제 배차**: 기사를 골라 바로 배정. 기사 목록에 기사별 출발지까지 거리와 현재 진행 중인 건수 표시
- 배차 회수, 재배차, 취소, 상태 되돌리기
- 사진, 주유 기록, 상태 이력 보기

### 8.3 문의
- 오더별 채팅(고객 ↔ 관제, 기사 ↔ 관제). 안 읽은 문의 개수 표시

### 8.4 관리
- **기사 관리**: 가입 승인과 정지, 면허증과 보험 서류 확인, 기사별 수수료율 입력란(계산은 2단계)
- **업체 관리**: 업체 등록, 직원 계정 발급, 기본 결제 방식, **주유비 부담 방식(고객 청구 / 회사 부담)**. 업체별 단가표, 후불 한도, 미수금은 2단계.
- **요금표**: 거리 구간별 기본 요금, 미션 항목과 추가 요금
- **운영 설정**: 반납 가능 시간(탁송, 대리 따로), 예약 오더 간격(기본 30분), 미배차 경고 시간(기본 10분)
- 기존 업체, 기사, 주소 데이터는 관제 화면에서 직접 입력한다. 엑셀 일괄 등록은 필요할 때 추가한다. (Claude의 결정)

### 8.5 직원 등급과 변경 기록
- **관리자**: 전부 가능. 직원 계정, 요금표, 수수료율, 업체 설정 변경은 관리자만 가능.
- **일반 관제**: 오더 접수, 수정, 배차, 문의 처리, 기사와 업체 조회.
- 누가 언제 무엇을 어떤 값에서 어떤 값으로 바꿨는지 모두 기록하고 관리자가 볼 수 있다.

## 9. 요금과 결제 (1단계 범위)

- 기본 요금 = 출발지 → (경유지) → 도착지 도로 거리를 구간표에 대입 + 미션 추가 요금
- 결제 방식: 오더마다 **현금 / 후불** 중 하나
- 수수료: 정률(%). 1단계에서는 기사별 비율만 저장한다.
- 주유비: 기본은 고객 청구, 업체마다 회사 부담으로 바꿀 수 있다. 1단계에서는 금액과 영수증만 기록한다.
- 현금 오더는 기사가 현금을 받는다. 수수료만큼 기사가 회사에 낼 돈으로 잡는 계산은 2단계.

### 9.1 앱 배포 (사용자 결정: 안드로이드 먼저)
- 1단계는 **안드로이드로 먼저** 시작한다. 아이폰용도 같은 코드로 빌드할 수 있게 만들어 두고, 필요해지면 애플 등록 후 배포한다.
- **개발과 시험 기간**: 안드로이드는 설치 파일(APK)을 기사와 고객에게 직접 보내 설치한다. 무료다. 아이폰은 이 방식이 안 된다.
- **정식 배포**: 구글 플레이 개발자 등록 1회 $25(약 3.5만 원), 애플 개발자 등록 연 $99(약 14만 원). 아이폰 사용자에게 주려면 시험 단계에서도 애플 등록이 필요하다.
- 앱 빌드는 Expo 무료 빌드 서비스(EAS, 월 무료 횟수 제한 있음)를 쓴다.

## 10. 목표 / 비목표 / 실패 조건

**목표**
- 소규모 실제 운영에 바로 투입할 수 있을 것
- 한 화면에서 바꾼 것이 다른 두 화면에 몇 초 안에 반영될 것
- 사진 없이는 운행 시작과 완료가 절대 불가능할 것

**비목표 (1단계에서 안 함)**
- 정산 계산, 청구서, 기사 지급
- 앱 내 카드 결제
- 개인 고객용 회원가입

**실패 조건 (기능은 돌아가도 실패로 봄)**
- 두 기사가 같은 오더를 동시에 잡을 수 있음
- 고객이 다른 업체의 오더나 주소를 볼 수 있음
- 기사나 고객이 사진 없이 진행할 수 있는 우회로가 있음 (관제의 사유 기록 예외만 허용)
- 반납 시간, 동시 보유 제한을 기사가 피해 갈 수 있음 (서버에서 검사해야 함)
- 기사 앱이 느리거나 버튼이 작아 현장에서 쓰기 어려움
- 운행 중 백그라운드 위치 전송이 배터리를 지나치게 닳게 함

## 11. 빌더에게 맡기는 것
- 화면 디자인과 세부 배치 (휴대폰에서 큰 버튼, 한 손 조작 우선)
- 데이터베이스 테이블 구조와 RLS 정책 작성 방식
- 위치 전송 간격 (배터리와 정확도 사이에서 판단)
- 사진 압축 크기
- 실시간 연동 구현 방식 (Supabase Realtime 채널 구성)
