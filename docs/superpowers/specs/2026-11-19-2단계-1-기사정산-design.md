# 2단계-1 기사 정산 (충전금 장부·출금 신청) 설계

- 날짜: 2026-11-19
- 앞 문서: `2026-11-16-1단계-오더흐름-design.md` (2단계 범위: 수수료, 주유비 정산, 현금·후불 정산, 업체 청구서, 미수금, 업체별 단가)
- 이번 문서 범위: **기사 쪽 돈** (회사 ↔ 기사). 업체 청구(회사 ↔ 업체)는 다음 문서 2단계-2.

## 1. 왜 만드는가

사용자는 기사에게 "충전금"으로 정산한다. 후불 오더는 회사가 나중에 업체에서 받으니 기사 몫을 충전금에 넣어 주고, 현금 오더는 기사가 고객에게 직접 받으니 회사 수수료를 충전금에서 뺀다. 지금은 이 계산과 출금 처리를 앱 밖에서 한다. 앱이 이 장부를 대신 들고, 기사는 앱에서 잔액·내역을 보고 출금을 신청하게 한다.

사용자가 정한 것 (2026-11-19 대화):

- 수수료 **20%**.
- **후불 오더**: 완료 **10분 뒤** 충전금에 들어온다. 들어온 돈은 **다음 날 낮 12시(한국 시간) 이후** 출금할 수 있다.
- **현금 오더**: 충전금에서 **수수료를 뺀다**.
- 충전금이 **마이너스면 배차를 막는다**.
- 기사가 **앱에서 직접 출금 신청**을 할 수 있어야 한다. 실제 송금 자동화(가상계좌·펌뱅킹)는 사용자가 요청할 때 붙인다 — **지금 그 자리를 만들어 둔다**.
- 충전금은 원래 "가상계좌에 들어 있는 돈"이고 앱과 연동돼야 한다. 가상계좌 서비스는 아직 없고, 연동은 **나중에** 한다.
- 장부 한 줄 이름은 **"후불 오더 완료 (오더번호)"** 처럼 오더 번호를 붙인다.

## 2. 목표 / 비목표 / 반드시 피할 것

목표
- 기사별 충전금 장부: 모든 돈 움직임이 한 줄씩 남고, 잔액은 그 합.
- 오더 완료 때 서버가 자동으로 장부에 적는다 (사람이 계산하지 않는다).
- 마이너스 잔액이면 기사 잡기와 관제 배정 모두 막는다.
- 기사 앱: 잔액, 출금 가능 금액, 들어올 예정 금액, 내역, 출금 신청, 받을 계좌.
- 관제 웹(관리자): 기사별 장부, 수동 충전, 수동 조정(사유 필수), 출금 신청 목록과 지급 완료·거절.
- 사람이 읽는 **오더 번호**를 모든 앱에 보인다.

비목표 (이번에 안 함)
- 가상계좌 입금 자동 반영, 자동 송금(펌뱅킹). 단, 나중에 붙일 자리(출금 신청의 상태·외부 거래 번호 칸)는 만든다.
- 업체 월말 정산서·부가세·미수금 (2단계-2).
- 업체별 단가표.

반드시 피할 것 (돌아가도 실패)
- 잔액이 장부 합과 어긋나는 것 (잔액을 따로 저장해 두고 따로 고치는 구조 금지).
- 같은 오더가 두 번 정산되는 것 (완료 → 다른 상태 → 다시 완료 등).
- 기사가 남의 장부·계좌를 보는 것, 기사가 장부를 직접 쓰는 것.
- 출금 가능 금액보다 많이 출금 신청되는 것 (동시에 두 번 눌러도).

## 3. 만드는 방법 (Approaches)

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| A. 장부(거래 내역) 행을 쌓고 잔액 = 합계 | 내역이 남아 확인·수정 쉬움, 나중에 가상계좌 결과도 한 줄로 추가 | 표 하나 더, 합계 계산 | **선택** |
| B. 기사마다 잔액 숫자 하나만 저장 | 가장 단순 | 왜 이 금액인지 알 수 없고 틀려도 못 찾음 | 제외 |
| C. 매번 오더에서 다시 계산 | 저장할 것 없음 | 충전·출금·조정 같은 오더 아닌 돈을 담을 수 없음 | 제외 |

사용자가 A와 순서(기사 정산 먼저, 업체 청구 다음)를 골랐다.

## 4. 오더 번호

- 형식: `MMDD-NNN` — 접수 날짜(한국 시간)와 그날 순번. 예: `1119-007`. **(Claude 제안)** 전화로 "오늘 7번"이라 말하기 쉬워서.
- 서버가 오더를 넣을 때 정한다(같은 날 순번이 겹치지 않게). 연도가 바뀌어 같은 번호가 생겨도 화면엔 날짜가 함께 보이므로 괜찮다; 저장은 연도를 포함한 고유값으로 한다.
- 기존 오더에도 접수 시각 순으로 채운다.
- 기사 앱·고객 앱·관제 웹의 오더 목록·상세, 알림 본문, 장부 줄 이름에 쓴다.

## 5. 장부 규칙

### 5.1 장부 한 줄
- 기사, 금액(+/−, 원 단위 정수), 종류, 이름(사람이 읽는 문구), 관련 오더(있으면), 사유(조정·거절 때), 만든 사람, 만든 시각,
- **들어오는 시각**(이때부터 잔액에 들어감), **출금 가능 시각**(+ 금액만; 이때부터 출금 가능).

### 5.2 종류와 금액
| 종류 | 언제 | 금액 | 들어오는 시각 | 출금 가능 시각 | 이름 |
|---|---|---|---|---|---|
| 후불 오더 정산 | 후불 오더가 완료됨 | +(요금 − 수수료) | 완료 + 10분 | 완료한 날(한국)의 다음 날 12:00 | 후불 오더 완료 (1119-007) |
| 현금 오더 수수료 | 현금 오더가 완료됨 | −수수료 | 완료 즉시 | — | 현금 오더 수수료 (1119-008) |
| 시작 잔액 | 정산을 켤 때 관리자가 입력 (기사당 한 번) | +/− | 즉시 | 즉시(+일 때) | 시작 잔액 |
| 주유비 지급 | 관제가 후불 오더 주유비 청구를 지급 (10장) | + | 즉시 | 즉시 | 주유비 지급 (1119-007) |
| 관리자 충전 | 관리자가 입력 | + | 즉시 | 즉시 | 충전 |
| 관리자 조정 | 관리자가 입력, 사유 필수 | +/− | 즉시 | 즉시(+일 때) | 조정: (사유) |
| 출금 신청 | 기사가 신청 | −신청 금액 (신청 순간 잡아 둠) | 즉시 | — | 출금 신청 |
| 출금 거절 | 관리자가 거절 | +같은 금액 (되돌림) | 즉시 | 즉시 | 출금 거절: (사유) |
| 정산 취소·변경 | 완료 오더의 요금이 바뀌거나 완료가 취소됨 | 이전 정산을 되돌리는 금액(+차이 반영) | 즉시 | 원래 줄과 같게 | 정산 변경 (1119-007) |

- 수수료 = 요금 × 수수료율, **원 단위 반올림**. 수수료율은 기사별 값(관리자만 변경, 1단계에 있음), 없으면 **회사 기본 20%**. 정산 시점의 비율을 장부 줄에 함께 남긴다(나중에 비율이 바뀌어도 과거 줄은 그대로).
- 요금에는 미션 추가요금이 이미 들어 있다.
- 한 오더는 **최종 상태 기준으로 한 번만** 정산된다. **(Claude 결정)** 정산은 "이 오더가 지금 상태라면 기사별로 장부에 얼마가 있어야 하는가"를 다시 계산하고, 이미 적힌 합과의 **차이만** "정산 변경" 줄로 적는다. 그래서 완료 후 요금 변경, 완료 취소, 기사 변경(전 기사는 되돌리고 새 기사에게 적음), 결제 방식 변경(후불↔현금)이 모두 같은 규칙으로 맞춰진다.
- **(Claude 결정)** 정산 변경에 쓰는 수수료율은 그 오더가 **처음 정산될 때 남긴 비율**이다 (그 사이 기사 비율이 바뀌어도 같은 오더는 같은 비율). 새 기사에게 처음 적힐 때는 그 기사의 그때 비율.
- **(Claude 결정)** 되돌리는 줄의 들어오는 시각·출금 가능 시각은 **되돌리는 원래 줄과 같게** 한다. 그래서 완료 10분 안에 되돌려도 잔액이 잠깐 마이너스가 되어 배차가 막히는 일이 없다.

### 5.3 잔액 세 가지 (기사 앱·관제 웹에 보임)
- **잔액** = 들어오는 시각이 지난 줄의 합. 배차 막기는 이 값 < 0 일 때.
- **출금 가능** = 잔액 − (아직 출금 가능 시각 전인 + 줄의 합). 0보다 작으면 0.
- **들어올 예정** = 아직 들어오는 시각 전인 줄의 합 (완료 10분 안 된 후불 정산).

### 5.4 배차 막기
- 기사가 오더를 잡을 때, 관제가 기사에게 배정할 때 잔액 < 0 이면 거절: "충전금이 부족해요(마이너스). 충전 후 다시 시도해 주세요." 관제 화면에서는 그 기사 옆에 잔액을 보인다.
- 이미 배정된 오더는 그대로 진행(운행 중에 끊지 않는다).

## 6. 출금

- 기사가 앱에서 금액을 넣고 신청. 금액은 1원 이상, **출금 가능 금액 이하**. 동시에 두 번 눌러도 합이 넘지 않게 서버가 한 번에 처리.
- 신청하는 순간 장부에 −금액(잡아 둠). 상태: **신청 → 지급 완료 / 거절**.
- 받을 계좌: 은행, 계좌번호, 예금주. 기사 본인이 앱에서 입력·수정, 관제(관리자)만 함께 봄. 계좌가 없으면 신청 불가.
- 관리자: 출금 신청 목록(신청 순), 기사·금액·계좌, **지급 완료**(직접 이체 뒤 누름, 메모 선택) / **거절**(사유 필수 → 되돌림 줄).
- 알림: 지급 완료·거절 때 기사에게 푸시.
- **나중 자동화 자리**: 출금 신청에 "처리 방식(수동/자동)", "외부 거래 번호", "실패 사유" 칸을 둔다. 가상계좌 입금은 "충전" 줄을 외부 거래 번호와 함께 쓰는 방식으로 붙인다.

## 7. 화면

기사 앱 — 새 탭 "충전금" (또는 내 정보 안):
```
충전금 잔액           28,000원
출금 가능             4,000원
들어올 예정           24,000원 (10분 뒤)
[출금 신청]   [받을 계좌]

11/20 13:00  출금 신청          −40,000  신청됨
11/20 09:00  충전               +50,000
11/19 22:10  현금 오더 수수료 (1119-008)  −6,000
11/19 21:00  후불 오더 완료 (1119-007)   +24,000  11/20 12:00부터 출금
```
- 잔액이 마이너스면 오더 목록 위에 빨간 안내 "충전금이 마이너스라 오더를 잡을 수 없어요".

관제 웹 (관리자):
- 기사 조회 화면에 잔액 열, 기사 상세에 장부·충전·조정.
- 새 화면 "출금 신청": 대기 목록과 처리.

## 8. 권한

- 장부·출금 신청: 기사는 **자기 것 읽기만**, 쓰기는 정해진 서버 함수(출금 신청)로만. 관제는 읽기, **충전·조정·지급·거절은 관리자만**(1단계 규칙: 수수료율 등 돈 설정은 관리자).
- 받을 계좌: 본인 읽기·쓰기, **관리자만** 읽기 (출금 처리가 관리자 일이므로; 일반 관제·고객은 볼 수 없음 — Claude 결정).
- 출금 신청 목록: 관리자만 (일반 관제는 기사별 잔액만 봄).
- 장부 자동 줄(오더 정산)은 서버 트리거만 쓴다.

## 9. 미리 생각한 경우

- 완료 10분 안에 관제가 상태를 되돌림 → 정산 변경 줄로 상쇄.
- 완료 후 관제가 요금을 고침 → 차이만큼 정산 변경.
- 수수료율이 0% 또는 100% → 그대로 계산(0원 줄은 남기지 않음 — **Claude 제안**).
- 요금 0원 오더 → 정산 줄 없음.
- 같은 날 순번 999 넘음 → 4자리로 늘어남.
- 기사 계정 정지 → 장부·출금은 그대로 동작(정지는 배차만 막음).

## 10. 주유비 (사용자 결정 2026-11-19)

- 누가 기사에게 주유비를 주는지는 **업체별 설정**이고, 기본값은:
  - **현금 오더 → 업체 지급**: 업체가 현장에서 기사에게 직접 준다. 앱은 영수증만 기록, 충전금 줄 없음. 기사 앱 영수증 옆에 "업체 지급".
  - **후불 오더 → 상황실 지급**: 회사가 기사에게 준다. 영수증이 올라오면 관제 화면 **"주유비 청구"** 목록에 대기로 뜬다.
- 관제는 주유비 청구를 **건별로 지급**하거나, 여러 건을 골라(또는 기사별·전체) **한 번에 지급**할 수 있다. 지급하면 기사 충전금에 `+금액` "주유비 지급 (1119-007)" 줄이 즉시 들어오고 즉시 출금 가능.
- 지급 전 영수증 금액이 고쳐지거나 지워지면 대기 금액도 따라 바뀐다. 지급 뒤 바뀌면 차이를 "주유비 변경" 줄로 적는다(정산과 같은 차이 방식).
- 업체에 주유비를 청구할지("고객 청구"/"회사 부담", 1단계에 있는 설정)는 업체 월말 정산서(2단계-2)에서 쓴다.
- **(Claude 해석, 승인 때 확인)** "관제에서 지급" = 일반 관제 직원도 주유비 지급을 누를 수 있다 (충전·조정·출금 처리는 관리자만).

## 11. 시작 잔액 (사용자 결정 2026-11-19)

- 사용자: 시작 잔액은 **기사별 가상계좌에 남아 있는 실시간 잔액**으로.
- 문제점 (사용자에게 알림): 가상계좌 서비스와 아직 연결되지 않아 앱이 그 잔액을 스스로 읽을 수 없다. 그래서 정산을 켜는 날 관리자가 그 시각의 가상계좌 잔액을 보고 기사별 **"시작 잔액"** 줄로 입력한다(관제 웹에 기사 목록 + 금액 칸으로 한 번에 넣는 화면). 그 전에 끝난 오더는 앱이 다시 계산하지 않는다(정산 켠 시각 이후 완료분만 자동 정산).
- 연결 전까지 가상계좌로 들어오고 나간 돈은 관리자가 앱에 "충전"·출금 처리로 같이 적어야 두 잔액이 맞는다. 연결 후에는 입금·송금 결과가 자동으로 장부에 들어오고, 하루 한 번 가상계좌 잔액과 앱 잔액을 비교해 다르면 관리자에게 알리는 기능을 붙인다(연결 때 함께).
