# 서류탁송 + 사진 검사 설계 (2026-11-27)

## 왜
캐피탈(할부·리스) 차량 탁송은 차와 함께 **서류**(자동차등록증, 인감, 캐피탈 양식)를 받아 와야 한다.
지금은 서류를 받았는지, 제대로 썼는지 앱이 모른다. 서류가 틀리면 다시 고객에게 가야 해서 시간과 돈이 샌다.
차량 사진도 잘리거나 비뚤게 찍혀 분쟁 때 증거로 못 쓰는 일이 있다.

**성공:** 기사님이 출발하기 전에 서류가 완전한지 확인되고, 틀리면 어느 사진이 왜 틀렸는지 현장에서 알고 바로 고친다.

## 목표 / 하지 않을 것 / 실패로 볼 것
- 목표
  - 오더 종류 3가지: 일반탁송(`takson`), 서류탁송(`docs`), 대리(`daeri`).
  - 서류탁송: 캐피탈 회사 선택, 서류 사진 칸, 인감 수량, 작성방법 예시, 관제 인정/불인정.
  - 차량 사진: 반듯하게·잘리지 않게 찍도록 촬영 때 막고, 관제도 불인정할 수 있게.
- 하지 않을 것
  - 유료 AI. 판단은 휴대폰 안(무료)과 관제(사람)만.
  - 서류 손글씨 내용 자동 판정(무료로 믿을 만하게 못 함 → 관제가 본다).
  - 대리 오더 쪽 변화.
- 실패로 볼 것
  - 예시 양식 사진이나 서류 사진이 공개 저장소(GitHub)나 공개 링크로 새는 것. 서류에는 주민번호 등 개인정보가 있다.
  - 관제가 못 보는 사이 기사님이 하염없이 기다리는데 이유를 모르는 것(대기 중 표시 필요).

## 사용자가 정한 것
1. 판단: **휴대폰 무료 자동 검사 + 서류 내용은 관제**가 인정/불인정.
2. 서류 종류: **자동차등록증**, **인감증명서/본인서명사실확인서**(줄여서 "인감"), **캐피탈서류**.
   - 인감: 잘 찍혔는지 + **수량**. **용도는 '일반용' 또는 '자동차공매용'**이어야 한다(관제 확인 항목, 2단계에서 글자 읽기로 보조).
3. 캐피탈 회사는 **오더 만들 때 고른다**(고객 앱·관제웹). 기사님은 그 회사 예시를 본다.
4. 예시 양식은 사용자가 준 사진(`예시서류/` 회사별 폴더, 약 22곳 154장)을 쓴다. 쓰지 않는 서류도 섞여 있다.
5. 서류는 **출발 전 올리고, 관제가 인정해야 [운행 시작]**이 눌린다.
6. 만드는 순서: **C. 두 단계** — 1단계(이 문서의 본론), 2단계 휴대폰 AI.

## 방법 비교 (사용자가 C 선택)
- A. 휴대폰 AI 전부 한 번에: 무료지만 개발용 앱을 새로 빌드해야 하고 대부분 실제 휴대폰에서만 시험 가능. 한 번에 하기엔 위험.
- B. 기울기 센서·테두리 안내 + 관제 판단만: 금방 쓰지만 차 잘림·서류 비뚤어짐을 기계가 못 잡음.
- **C. B를 먼저(1단계), A를 나중에(2단계)**: 바로 쓰면서 AI를 붙인다.
- 제외: 구글 Gemini 무료 등급(올린 사진이 학습에 쓰일 수 있어 개인정보 서류에 부적합), 유료 AI(사용자가 무료 원함).

## 1단계 설계

### 데이터 (Supabase, 새 마이그레이션 1개)
- `orders.kind` 체크에 `'docs'` 추가. 반납(취소) 시간·정산·청구는 일반탁송과 같게 취급(`kind <> 'daeri'`).
- `capital_companies(id, name, active, sort)` — 캐피탈 회사 목록. 관제(관리자)만 고침.
- `capital_examples(id, company_id, seq, title, path, is_cover)` — 회사별 예시 사진. `is_cover`는 표지(사진 칸을 만들지 않음).
- `orders.capital_company_id`(서류탁송이면 필수), `orders.seal_count`(인감 수량, 기사님이 입력, 1 이상).
- `order_documents(id, order_id, kind, example_id, path, status, reason, reviewed_by, reviewed_at, taken_at)`
  - `kind`: `'registration' | 'seal' | 'capital'`. 칸: 등록증 1칸, 인감 1칸(여러 장이면 한 장에 펼쳐 찍기 — 아래 "남은 것" 참고), 캐피탈 = 그 회사의 표지 아닌 예시마다 1칸(`example_id`).
  - `status`: `'pending' | 'approved' | 'rejected'`. 다시 찍으면 `pending`으로 돌아가고 `reason` 지움.
- 차량 사진 불인정: `order_photos`에 `rejected_reason text`(null이면 정상). 관제가 적으면 그 칸은 "빠짐"으로 친다.
- 저장소: 비공개 버킷 `capital-examples`(로그인한 기사·관제·고객 읽기, 관리자만 쓰기), 서류 사진은 기존 `order-photos` 버킷 `{order}/docs/...` (기존 읽기 권한 규칙 그대로).

### 서버 규칙
- `create_order`: `kind='docs'`면 `capital_company_id` 필수(`CAPITAL_REQUIRED`).
- `missing_documents(order)`: 빠졌거나 불인정인 서류 칸 목록 + 인감 수량 미입력.
- `advance_order` (수락함 → 운행 중): 서류탁송이면 서류가 **모두 올라오고 모두 인정**되어야 함. 아니면 `DOCS_REQUIRED` / `DOCS_NOT_APPROVED`.
- `missing_photos`: `rejected_reason`이 있는 칸도 빠진 것으로 돌려준다(일반·서류 모두).
- 관제 함수 `review_document(id, ok, reason)`, `reject_photo(id, reason)` — 관제만. 불인정이면 기사님께 푸시("서류 다시 찍어 주세요: 인감 — 용도가 달라요").
- 이력(order_events)에 인정/불인정 남김.

### 기사 앱
- 주문 목록 카드: 서류탁송이면 주황색 **"서류"** 표시(+ 캐피탈 회사 이름).
- 오더 상세(오더수락 뒤, 출발 사진 아래) **서류 사진** 카드:
  - 칸마다 상태: 찍기 / 대기 중(관제 확인 중) / ✓ 인정 / ✗ 불인정 + 이유(빨간 글씨).
  - 인감 수량 입력칸.
  - [작성방법 예시 보기] → 그 회사 예시 화면.
  - 맨 아래 안내: "관제 확인을 기다리는 중이에요" (모두 올렸는데 인정 전).
- [운행 시작] 버튼 안내에 서류 이유 추가("서류 2장이 관제 확인 중이에요").
- 아래 탭 **"서류 예시"**: 캐피탈 회사 목록 → 회사별 예시 사진(확대 가능). 오더 없이도 볼 수 있음.
- 카메라(차량·서류 공통 1단계 검사):
  - 화면에 **맞춤 테두리**(차량: 가로 큰 사각형, 서류: A4 세로 사각형).
  - (기울기 센서 검사는 1단계에서 뺌 — 사용자 결정 2026-11-27)
- 서류 사진도 기존 업로드 대기열(신호 없으면 나중에 올라감) 재사용.

### 관제웹
- 오더 상세: 서류 사진 칸(등록증·인감·캐피탈 각 칸) + 인감 수량. 칸마다 [인정] / [불인정] + 이유 고르기(잘림, 흐림, 빠진 칸, 도장·서명 없음, 용도 틀림(일반용·자동차공매용 아님), 수량 다름, 기타 직접 입력).
- 차량 사진 칸에도 [불인정] + 이유.
- 관제판 목록: 서류탁송 표시, "서류 확인 대기" 오더는 눈에 띄게(확인 늦으면 기사님이 기다림).
- 오더 만들기·수정: 종류 3개, 서류탁송이면 캐피탈 회사 고르기.
- 설정(관리자): 캐피탈 회사 추가·숨김, 회사별 예시 사진 올리기·지우기·순서·표지 표시.

### 고객 앱
- 오더 만들기: 종류 3개(일반탁송·서류탁송·대리), 서류탁송이면 캐피탈 회사 고르기.
- 오더 상세: 종류 표시. 서류 사진은 고객도 볼 수 있음(기존 사진 보기 화면에 추가).

### 예시 사진 옮기기
- 일회용 스크립트로 `예시서류/` 회사 폴더 → `capital_companies` + `capital-examples` 버킷(압축해서). 첫 장이 표지 그림이면 `is_cover`.
- `예시서류/` 폴더는 **GitHub에 올리지 않는다**(`.gitignore`).
- 쓰지 않는 서류는 사용자가 올리기 전 폴더에서 빼거나, 올린 뒤 관제웹에서 지운다.

## 2단계(나중) — 휴대폰 무료 AI
- 개발용 앱(EAS development 빌드)을 새로 만들어야 함. 브라우저 미리보기로는 시험 불가.
- 차량: 휴대폰 안 물체 찾기로 차 상자를 찾고, 사진 가장자리에 닿으면 "차가 잘렸어요".
- 서류: 구글 ML Kit 문서 스캐너로 모서리 찾기·반듯하게 펴기, 모서리가 화면 밖이면 다시 찍기.
- 인감: 글자 읽기로 "일반용"/"자동차공매용" 글자 확인 → 관제 화면에 "용도 글자 확인됨/못 찾음" 보조 표시.
- 2단계는 별도 설계·계획으로.

## 남은 것 (만드는 사람 판단, 고치려면 말해 주세요)
- 인감이 여러 장이면 **한 장에 펼쳐서 한 번**에 찍는다(칸 1개) + 수량 입력. 관제가 사진 속 장수와 수량을 맞춰 본다.
- "서류" 표시 색은 주황(예약 표시와 같은 경고색).
- 서류 사진은 차량 사진과 같은 압축 크기.
- 불인정 이유 목록은 위 기본값, 관제가 "기타"로 직접 쓸 수 있음.
- 관제의 차량 사진 불인정은 그 사진을 다시 찍을 수 있는 동안만 된다(출발 사진은 운행 시작 전, 도착 사진은 완료 전).
